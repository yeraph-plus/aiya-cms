\### 2. Notification challenge 安全闭合



当前目标必须同时满足：



\- 注册、邮箱验证、密码重置不返回 token。

\- challenge token 使用受保护存储，不能以明文长期保留。

\- 到期后可清理，重试期间仍可完成投递。

\- 重试次数由代码常量控制，并与密码重置策略一致。

\- Mailpit 验证真实邮件链路、失败重试、死信和恢复。



新增测试：



\- token 不在响应体。

\- token 不在 notification 管理接口。

\- token 不在日志和事件。

\- TTL 到期清理。

\- SMTP 失败按常量重试，超过次数进入失败状态。

\- Mailpit 收到注册、验证、重置邮件。

\## 阶段 2：High 后端问题



\### 1. 挂载通知管理路由



当前管理员 SPA 已有通知工作台，但 `management\_plane` 未挂载 `notifications\_admin`。



修复：



\- 将通知管理路由加入管理 manifest。

\- 增加 404 回归测试。

\- 验证列表、详情、重试、取消、失败状态查询。



\### 2. 限流和失败锁定



保持现有合同：



\- 密码重置：每账号/来源每小时最多 5 次。

\- 注册：不限制。

\- 登录：增加账号维度和来源维度失败限制。

\- 超限统一返回 429。



同时修复：



\- 可信代理下的真实客户端 IP 解析。

\- Nginx `X-Forwarded-For` 信任边界。

\- in-process 限流状态无界增长。

\- 多进程/多实例时使用 Redis 或明确限制为单实例部署。



新增测试：



\- 同一账号不同 IP。

\- 同一 IP 不同账号。

\- 代理链伪造。

\- 限流窗口过期。

\- 限流键数量有界。

\- 429 响应合同。



\### 3. 注册后角色和通知一致性



当前注册、默认角色分配、通知投递存在跨事务风险。



需要选择并落实一种方案：



\- 事务 outbox + 幂等 worker；或

\- 可恢复的注册 workflow，失败后可补偿；或

\- 明确的状态机和后台重试任务。



必须覆盖：



\- 用户创建成功但角色分配失败。

\- 用户创建成功但通知发送失败。

\- 重试不重复创建用户、不重复赋权。

\- 管理员可以看到失败状态并重试。



\### 4. Membership 与 PointsLedger 事务一致性



当前积分发放可能先提交，会员事务后失败，造成孤立积分。



需要：



\- 增加故障注入测试。

\- 统一幂等键。

\- 使用 outbox/workflow/补偿机制保证最终一致。

\- 明确积分发放结果合同，不能只返回 `entry\_id` 却声明完整余额结果。



\### 5. Redis 生产 fail-fast 和健康检查



修复：



\- 生产环境缺少 Redis URL 时启动失败。

\- 设置连接超时、关闭策略。

\- 健康检查区分数据库和 Redis。

\- 管理会话依赖 Redis 时，readiness 必须反映 Redis 状态。
