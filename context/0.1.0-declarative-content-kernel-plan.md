## 1. 目标

把现有 content、taxonomy、comment 的通用基实现提升为内核组件，以声明类登记 post、forum、issue 三种业务内容类型，并保持当前单 type URL 隔离、统一查询、taxonomy 组合筛选和评论树能力。

完成后：

- `inc/kernel/content` 拥有 Content 基实现和声明解释器；
- `inc/kernel/taxonomy` 拥有 taxonomy 基实现；
- `inc/kernel/comment` 拥有 comment 基实现；
- `inc/modules/post|forum|issue` 只保存类型声明和该类型自己的扩展业务；
- `GET /api/v1/content-types` 是管理端内容建模元数据的唯一 HTTP 契约；
- `inc/modules/content|taxonomy|comment` 不再存在兼容包装。

## 2. 非目标

- 不实现 Meilisearch、跨 type 查询或搜索排序；`q` 仍为 SQL 字面包含匹配。
- 不实现树形 taxonomy、term 合并、版本历史或修订。
- 不实现按 type Capability、物理分表或每行延迟删除任务。
- 不把 interaction、SEO 或业务专用字段塞入内核声明解释器。

### G1 — 红测：声明解释器与架构边界

新增失败测试：

1. `ContentType` 缺少必填声明、重复/非法 `type_name`、非法默认状态或未知 transition 起止状态。
2. 重复 field/group/status/action、非法纯函数 validator、注册后修改或重复注册。
3. data 未知键、缺少 required 字段、bool/number/url 规范化失败，以及持久化值全部为字符串。
4. kernel 不导入 modules；modules 只导入 kernel 公开声明接口；API 显式登记三个类型。
5. registry freeze 后写入失败；应用启动时完整性校验 fail-fast。

### G3 — Content 基实现迁入 kernel

先补红测，再迁移：

1. 把 Content ORM、Repository、UoW、Service、DTO、事件、错误码和 wiring 移到 `inc/kernel/content`。
2. Alembic 新增：
   - `contents.excerpt`：非空文本，默认空字符串；
   - `contents.comment_count`：非空 bigint，默认 0；
   - `contents.trashed_at`：可空 timestamptz。
3. 保留 `updated_at` 作为修改时间；Create/Update/Read DTO 加入 excerpt/comment_count/trashed_at。
4. 固定 Enum 改为注册定义驱动：请求 status 为 str，Service 按 type 校验；动作按 transition 定义执行。
5. trash 写 `trashed_at`；restore 回到 default_status；purge 仅处理到期 trash。
6. trash/restore 分别发布 `content.trashed`/`content.restored`；`content.deleted` 只用于物理删除和关联清理。
7. 查询更新：`q=title|slug|excerpt`，sort 增加 `comment_count`，继续支持 `updated_at` 范围/排序和 id tie-breaker。
8. 删除旧 `ContentTypeDef`、固定 `ContentStatus` 和固定 `TransitionAction`，不提供 alias。

当前进度：Content ORM、DTO、Repository、UoW、Service、事件、错误码、wiring 和 `0010_declarative_content_columns` 已迁入 `inc/kernel/content`；API 已切换到 kernel DTO/Service，并接入 taxonomy 组合筛选、评论统计和 recount。G3/G7/G8 受影响测试全绿；旧模块已在 G8 删除。

退出条件：content CRUD、状态、trash、组合 query、权限和读路径零写测试全绿。

### G5 — Comment 基实现迁入 kernel

## 5. 数据迁移顺序

1. 创建新增列并设置 server default，回填现有行。
2. `excerpt=''`、`comment_count` 通过评论表按冻结口径回填、`trashed_at` 对现有 trash 行设为迁移时间。
3. 如存在 `group='tags'`，一次性迁移为 `tag`；迁移后不接受 `tags`。
4. 将 data 中可转换的标量规范化为字符串；未知键的处理规则在 G0 类型规格中逐 type 登记，禁止实现期静默猜测。
