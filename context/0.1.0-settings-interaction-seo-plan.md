# 0.1.0 settings, interaction, and SEO execution slice

This document records the accepted execution boundary for the next implementation batch.

1. Expand `site.profile` into the declarative settings group and replace generic HTTP dictionaries with interpreter-generated metadata and sparse user-value contracts.
2. Add `/api/v1/public/settings` with an explicit public projection.
3. Consume registration policy through the API composition root, enforce it again in auth, and add one-time password reset through the existing mail outbox.
4. Replace content `rating` with user-interaction aggregates and add the minimal interaction relation/API slice.
5. Freeze SEO's backend data/SSR boundary only; no OG fields or sitemap/robots implementation in this release.

The execution sequence is specification and ADR -> failing tests -> implementation -> OpenAPI regeneration -> administrator UI -> PostgreSQL/Mailpit/Playwright integration.
